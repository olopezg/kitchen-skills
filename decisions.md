- 2026-10-08. **The supervisor spares processes older than the job, not processes that start between jobs** (issue #61, PR #62). The sweep and the next acquire leave alone what was running when the job started (pid and start time, `<lock>.before`). A process that starts between two jobs and holds the clone still keeps the next job waiting: at acquire time, the previous job's leftovers also predate the incoming job, and a respawning leftover cannot be told apart by start time. Docker Desktop's VM holds the clone only once a job bind-mounts it, so it is always older than that job. Scope: `automation/lib/supervise.py`. Revisit if a real daemon that starts between jobs keeps a project busy.
